# KiCad PCB プラグイン集

選択したフットプリントの自動整列・最密配置、ベタ（銅箔ゾーン）作成、
配線の最短化リファクタリングのための KiCad 10 Action Plugin 集。

ツールバーには **パレット（[pack_launcher.py](pack_launcher.py)）のボタン1つだけ**が表示される。
ボタンはトグルで、押すたびに常駐パレットの表示/非表示が切り替わる。
各ツールは従来どおり「ツール → 外部プラグイン」のメニューからも直接実行できる
（`show_toolbar_button = False` にしてツールバーから外しただけで、登録自体はされている）。

## インストール

### 初回セットアップ（プラグインフォルダを開く）

1. KiCad の PCBエディタを開く。
2. メニューの「ツール → 外部プラグイン → プラグインフォルダを開く」を選択する。
   - このフォルダが未作成の場合は KiCad が自動的に作成したうえで
     エクスプローラーで開いてくれる（手動でパスを探す必要はない）。
   - このリポジトリの中身（`.py` ファイル一式）をそのフォルダに配置する
     （このフォルダ自体を `git clone`/コピーしてもよい）。
3. PCBエディタに戻り、「ツール → 外部プラグイン → プラグインを更新」を実行する。
   - 各プラグインがツールバー（`show_toolbar_button = True` のもの）と
     「ツール → 外部プラグイン」のメニュー一覧に表示される。

### 2回目以降

コードを変更した場合は、毎回「ツール → 外部プラグイン → プラグインを更新」を
実行しないと反映されない（KiCadの再起動でもよい）。

## 共通の考え方

- **コートヤード基準**: 部品同士の間隔は原則としてコートヤード（`F_CrtYd`/`B_CrtYd`）の
  枠線の中心線を基準に計算する。図形の `GetBoundingBox()` は線幅ぶん外側に膨らむため、
  線幅/2だけ内側に縮めてから使う（`courtyard_bbox()`）。
  コートヤードが無い部品はテキスト抜きの実体BBoxにフォールバックする。
- **選択範囲のみを対象**とし、選択外の部品・ネットは無視する。
- **距離0 = 隙間なく密着**（コートヤード同士がちょうど接する状態）を「最密」とする。
  異なるネットのパッドが実際に接触しないよう、通常は `GAP_NM` を数百μm程度に設定して使う。

## プラグイン一覧

### [pack_launcher.py](pack_launcher.py) — PCB Tools Palette（常駐パレット）

ツールバー唯一のボタン（青い格子アイコン [pack_tools_icon.png](pack_tools_icon.png)）。
押すたびに**常駐パレットの表示/非表示がトグル**する。パレットは非モーダルなので、
開いたままpcbnewを操作でき、×ボタンやEscでも破棄されず隠れるだけ（検索文字列などの状態は保持）。
一覧は **HTML/CSS/JS（WebView2）** で描画される。

- **カテゴリ別セクション + アイコン付きカード**: `plugin.category` がセクション見出しに、
  モジュール変数 `ICON`（絵文字1つ）がカードのアイコンになる。
- 一覧は**表示のたび+↻ボタンで自動検出**する: このフォルダに ActionPlugin サブクラスを
  含む `.py` を置くだけで、コード修正なしに一覧へ追加される
  （新規ファイルはKiCadの「プラグインを更新」も必要。既存ファイルの編集反映も同様）。
- カードのタイトルには各モジュール docstring の **1行目（短い日本語の要約）** を表示し、
  2行目以降の詳細は**選択したカードだけ**に展開表示する。
  新しいツールを書くときは「1行目=要約、空行、以降=詳細」の形式で docstring を書く。
- **検索ボックス**でツール名・説明文から絞り込める。
  キーボード操作: ↑↓で選択、Enterで実行、Escで隠す（ダブルクリックでも実行）。
- **実行中は多重実行をロック**し、フッターに「実行中: …」を表示する
  （WebView2は別プロセス描画なので、本体が計算中でもパレットの表示は生きている）。
  実行時エラーはメッセージボックスで表示する。
- **実行はKiCad本体のメニューイベント経由**（`run_tool()`）: `Run()`を直接呼ぶと
  KiCadの「実行前後スナップショット→Undoエントリ作成」（`RunActionPlugin`）を
  素通りし、**Ctrl+Zが「some items not found」で壊れる**。パレットは
  「ツール→外部プラグイン」のメニュー項目を探して本物のコマンドイベントを
  同期発火することで、純正のUndoに乗せている（メニューに無いときだけ直接Run）。
- OSのダークモードに追従する（`prefers-color-scheme`）。
- **WebView2 が使えない環境では wx 標準ウィジェットの一発モーダルに自動フォールバック**
  するので、このフォルダごと別マシンに持って行っても動く。
- ランチャー自身と `_` 始まりのファイルは一覧から除外する。
- 実装: `wx.Frame` + `wx.html2.WebView`（Edgeバックエンド）。JS側から
  `window.kicad.postMessage(JSON)` でPython側へ実行/隠す/再検出を通知する双方向構成。
  「プラグインを更新」でモジュールが再importされると、旧パレットは自動破棄して作り直す。

#### ツール追加の規約（まとめ）

1. ActionPluginサブクラスを含む `.py` をこのフォルダに置く
2. docstring: 1行目=短い日本語要約（カードタイトル）、空行、以降=詳細（選択時に展開）
3. `ICON = "🧱"` （絵文字1つ、省略可。無ければカテゴリ既定アイコン）
4. `self.category` がセクション見出しになる（"Placement"→「配置」、"Zones"→「ベタ」。
   対応表はpack_launcher.py内の `CAT_JA`）

### [dense_pack.py](dense_pack.py) — Dense Pack Selected (zero gap)

選択部品を、**今の配置構造（行・列・並び順）を保ったまま**コートヤード距離0に詰め直す。
最短配線などは考慮しない、単純な「隙間詰め」ツール。

- **角ボタン（↖↗↙↘）はその角への重力詰め**: 「横に寄せる→縦に落とす」を
  動かなくなるまで繰り返すテトリス的コンパクション。滑る方向にしか動かないので
  ブロック同士の前後関係は崩れず、L字型など行に分けられない配置でも詰まる。
- **辺ボタン（←→↑↓）はその方向へ詰めつつ、直交軸は中央揃え**
  （行ベース: 例=← は行を左に詰めて、行内の背の低い部品は上下中央に置く）。
- **中央ボタン●は行・列の構造を保った対称詰め**: Y範囲が**過半**
  （低い方の高さの `ROW_OVERLAP_FRAC` = 50%以上）重なる部品同士を同じ「行」と
  みなし、行内は左→右・行同士は上→下の順序を維持したまま詰めて、
  幅の狭い行は中央寄せ・背の低い部品は行内で上下中央にして対称にする。
- **すでにコートヤード同士が接している（距離0または重なり、許容 `TOUCH_TOL_NM` = 1µm）
  部品群は1つのブロック**として扱い、内部の相対位置を崩さずまとめて動かす。
  同じ整列で再実行しても配置は変わらない（冪等）。
- 実行時に**3x3のボタン**で詰める方向を選ぶ（ボタン＝重力の向き。詳細は下記）。
- 部品を意図した並びに置いてから実行すると、その並びのままギャップ0になる。
- **「パッドにつながる配線も一緒に動かす」チェック**（既定ON）で、移動する
  パッドに乗っている配線が接続を保ったまま追従する:
  - つながる先がすべて同じ量だけ動く連結配線（ブロック内配線など）は
    **形を保ったまま平行移動**。
  - 動かない側にもつながる配線は、**分岐・ビア・タップ・円弧のない一続きの
    区間（run）単位**で処理する: 両端が同じ量だけ動くrunは形を保って平行移動、
    違う量動くrunは**古い形を捨てて端点間を45度+軸方向で引き直す**
    （うねった多セグメント配線も1本のきれいな経路にまとまり、中間の線分は
    削除される）。経路は**候補（L字2種+Z字3種）を移動後の盤面に当たり判定**
    して、他ネットの銅（配線・ビア・パッドBBox）にネットクラスの
    クリアランス未満で近づかない最初の候補を選ぶ。ビア/パッドの**ドリル穴は
    独立した障害物**として基板セットアップの穴クリアランス（`m_HoleClearance`、
    銅ルールとは別）を適用する。**全候補が塞がっている
    区間は track_shorten の遅延障害物A*で迂回路を探索**する(1区間
    `SEARCH_TIME_S`=3秒まで)。それでも見つからない区間だけ既定のL字で
    引いた上で、終了時に箇所数を警告する。変形する線分の
    途中に他の配線がT字接続している場合は接続点で分割して接続を保つ。
    パッド内ビア（via-in-pad）とそこにつながる別層の配線も追従する。
  - 仕上げに**要素（パッド/ビア/他の配線/ゾーン）につながらない端を持つ
    線分を連鎖的に削除**する（移動先が接続点と重なって潰れた線分の残骸や、
    自由端のかけらが残らない）。掃除の範囲は今回伸縮の対象になった
    グループ内だけ。ゾーンは**BBox内なら接続扱い**（塗りの連結はヘッドレスで
    判定できないため保守的に残す）。円弧は削除しない。
  - 円弧は伸縮できないため追従せず、終了時に本数を警告する。
  - パッドとの接続は配線の**端点（とビア位置）**で判定する。パッド上を
    端点なしで横切るだけの配線は接続として認識しない。
  - ロックされた配線も接続維持のため追従する（track_shorten と異なり
    スキップしない）。
  - **「仕上げに配線を短縮する」チェック**（既定ON）で、詰めたあとに
    track_shorten を盤面全体に1回かける。整列は「他の配線は動かせない」
    前提で自分の区間だけ通そうとするため、他ネットに塞がれた区間が
    残ることがあるが、仕上げの短縮は**塞いでいる側の配線も動かせる**ので
    大半が解消する（手動で短縮ボタンを押すのと同じ。進捗ダイアログ+中止可）。
  - 当たり判定は伸縮区間の経路選びだけに使う。剛体移動する配線束や
    部品自体の移動先が他の銅と重なることはチェックしない（DRCは別途）。
    パッドは実形状でなくBBox近似。
- 中央●の行ベース詰めでは、複数行にまたがる背の高いブロックがその「行」の
  高さを決めるので、隣に並んだ低い部品の下には空きが残る。角ボタンの重力詰めは
  行に縛られないため、こうした空きにも入り込む。

### [min_wire_pack_rot.py](min_wire_pack_rot.py) — Min-Wire Dense Pack Selected (rotate 90)

選択部品を最密に詰めつつ、**配線（ラッツネスト）総延長が最短になるよう配置と
90度刻みの回転**を最適化する。

- 配置エンジンはスカイライン法: 部品を1つずつ、既存部品に密着する候補位置
  （左寄せ／右寄せ）のうち、ネットのHPWL（パッド群BBoxの半周長の総和）+
  高さ増加ペナルティが最小になる場所に置く。
- 部品を置く**順番**を、5個以下なら全順列総当たり、6個以上は焼きなまし法
  （`TIME_BUDGET_S` 秒）で最適化する。
- 各フットプリントを実際に90度ずつ回転させて4方向の形状・パッド位置を実測してから
  元の向きに戻す（座標変換を手計算しないため回転方向の取り違えが起きない）。
- 形状・パッド配置が回転で変化しない対称な向きは自動的に候補から除外する。
- 部品を置くたびに「4方向 × 候補位置」を全評価し、配線長最小の置き方を選ぶ。
- 実行中は**進捗ダイアログ**（経過バー・フェーズ・ラウンド数・改善回数・評価値）を表示し、
  暫定ベストの配置を基板にも随時描画する（間隔は `LIVE_UPDATE_S`）。
  **「中止」ボタン**でその時点のベスト配置のまま確定して終了できる。

### [track_shorten.py](track_shorten.py) — Shorten Tracks (45deg reroute)

**遠回りしている配線を45度配線で引き直して短くする。**
配線（トラック）を選択して実行するとその配線から辿れる連鎖だけ、
何も選択していなければ全配線が対象。設定ダイアログで「実行」を押すと、
迂回率（実長÷45度制約の理論最短長）の悪い順に1本ずつ引き直す。

- **作業単位はコネクション**: パッド・ビア・分岐点（T字）・円弧との接続点を
  「端子」とし、端子間の同一層セグメント連鎖だけを引き直す。ビア・分岐点は
  動かさない（**ビアの追加・削除はしない**。層の乗せ替えが必要な最短化は対象外）。
- **パッド上の接続点はすべてパッド中心に正規化**: 端点だけでなく、パッド上に
  乗っている合流点（逆T字など）もグラフ上は「パッド中心」という1つのノードに
  集約する。各枝はそれぞれパッド中心を目標に引き直され、確実に
  **パッド中心 to パッド中心**の接続になる。物理端点と中心のズレは接続長に
  算入し、ズレがある連鎖は経路長が同じでも中心へ張り直す。
- **近接吸着は「繋がっていない点対」だけ**: 実セグメントで直接結ばれている
  2点は吸着しない（45度経路の曲げ端数の微小セグメントを潰すと、
  端点ズレ扱い→張り直しの無限往復になるため）。
- **微小セグメントは「点」に収縮する**: 長さが `JOIN_TOL_NM`（0.1mm）以下の
  セグメントは両端ノードを1つに統合し（パッド中心>ビアの優先で動かせない点を
  代表に残す）、断片自体は連鎖に併合して引き直しと一緒に削除する。
  微小断片が偽の分岐点や「幅が途中で変わる」スキップを作って連鎖を細切れに
  するのを防ぐ。新しく引く経路側も、吸着許容以下の微小セグメントは角を統合して
  作らない（統合で線が厳密な45度からズレることがあるが、ズレ幅は吸着許容以下）。
- **同じ2点間の平行（重複）エッジは1本に代表させる**: 引き直しは同ネットの銅を
  障害物にしないため、新経路が既存の同ネット配線に重なることがある。重なった
  配線をそのまま扱うとノードの次数が膨らんで偽の分岐点になるので、グラフには
  代表1本だけを載せ、残りは代表を含む連鎖の引き直しと一緒に削除する
  （＝重複銅は次の実行で自動的に掃除される）。
- **セグメント途中の合流も分岐点として認識する**: KiCadはセグメントを分割せずに
  T字タップを作れるため、センターライン上に乗っている同ネットのトラック端点・
  ビア・パッド中心で連鎖を論理分割する。元トラックの一部だけを引き直す場合、
  残り部分は同じ形で復元される。
- **数十µmズレた端点合流は吸着する**: 手配線では端点同士が完全一致せず
  数十µmズレたまま銅の重なりで導通していることがある。同ネットの端点・ビア・
  パッド中心が `JOIN_TOL_NM`（0.1mm）以内に密集していたら1つの接続点として
  扱い、正しく分岐と認識する（ズレはトラック幅より十分小さいので導通は保たれる）。
- **採用基準は「短くなる、または同長で曲げ数が減る」**: 経路長が
  `MIN_GAIN_NM` 以上短くなる場合に加え、長さが同じでも折れ曲がり数が
  現状より減るなら引き直しを採用する(曲げ数は単調減少なので収束する)。
- **行き止まりのヒゲは吸収**: 分岐点にぶら下がる、どこにも繋がらない短いスタブ
  （`STUB_MAX_MM`=3mm以下）は、合流先の連鎖を引き直すときに一緒に削除する。
  パッド・ビアに繋がる枝や、それより長い宙ぶらりん（配線途中のドラフトかも
  しれない）は消さない。
- **銅の上に乗ったゴミ断片も吸収**: 連鎖の銅に触れているが、他のどの同ネット
  銅（配線・ビア・パッド）にも触れていない短い断片（`STUB_MAX_MM`以下。
  編集で残った微小なカス）は、引き直しと一緒に削除する。他の銅への橋渡しを
  している断片は従来どおり安全のためスキップする。
- **経路探索は連続空間の可視グラフ+A\***: 障害物（他ネットの配線・ビア・パッド・
  基板外形・**配線禁止のルールエリア**）をクリアランス+線幅/2 だけ膨張させた
  矩形の角をノードにし、ノード間を「曲げ1回のL字2種+等長のZ字数種」の
  45度経路で結んで探索する（45度制約では等長最短が無数にあり、密集地帯では
  L字が塞がっていてもZ字なら通ることが多い）。
- **遅延障害物方式**: まず障害物なしで最短を引き、その経路に実際に当たった
  障害物だけを探索対象に加えて引き直す、を収束まで繰り返す。部分集合で
  経路が無ければ全障害物でも無い（打ち切りは健全）、毎回1件以上加わるので
  必ず停止、採用経路は毎回全障害物に対して検証。ノードが「実際に邪魔な
  障害物の角」だけになるため、ビア格子225本の中を縫うケースでも0.01秒で
  ほぼ理論最短が出る。
  グリッドに依存しないので、任意座標にある既存パターンとそのまま噛み合う。
  ノード数は `MAX_NODES` で上限を設け、上限に達して経路が見つからなかった
  場合は理由表示にその旨を出す（見落としの可能性）。
- **衝突判定は KiCad 自身のエンジン**（`GetEffectiveShape().Collide()`）。
- **クリアランスはプロジェクトルールを相手ごとに解決**: 障害物ごとに
  「自ネットのルール値」と「相手のルール値」の大きい方を適用する
  （KiCadの基本ルール解決と同じ。ネットクラス値・ローカル上書き・
  `GetOwnClearance` の解決値の最大。基板外形は銅-エッジクリアランス設定も
  尊重）。ダイアログの「クリアランス下限」はその下限として働く
  （初期値は Default ネットクラス）。
- **ホールクリアランス（穴-銅の別ルール）も守る**: 他ネットのビア・
  スルーホールパッドの**ドリル穴**を独立した障害物として扱い、基板セットアップの
  「穴あき部分の間隔」（`m_HoleClearance`）を適用する。銅の無い穴
  （NPTH取付穴）や別層のスルーホールの穴も避ける。
- **曲げ回数も減らす**: 経路長を増やさない範囲で、部分区間を「曲げ1回以下の
  等長接続」に張り直す後処理を行う（等長でも無駄にジグザグした形にしない）。
- **SWIG列挙はスナップショットに集約**: GUI実行中に `board.GetTracks()` 等の
  列挙が稀に `'SwigPyObject' not iterable` で壊れる（実測）ため、基板の列挙は
  各周の頭の1回だけにし、失敗時はリトライする。個別の連鎖で例外が出ても
  全体は止めず、スキップ件数を最後に報告する。
- **短くなり、かつ無衝突のときだけ置き換える**単調改善なので安全。全体を
  何周か繰り返し（最大周回数はダイアログで指定）、改善が無くなった周で
  自動終了する。1本の短縮が別の配線の障害物をどけるので、周回に意味がある。
- **クラッシュ対策（計画→一括反映）**: 探索中は基板に一切触らず「計画」だけを
  作り（計画済みの新経路同士も衝突チェックする）、各周の最後に一括で
  Remove/Add して接続情報を作り直す。反映中はGUIイベントを回さない。
  実行前に選択も自動解除する（選択中アイテムのRemoveはクラッシュの前科がある）。
- **「部品の下も通る」**（既定ON）を外すと、コートヤードも障害物として避ける。
- 進捗ダイアログの**「中止」でそこまでの結果を確定**して終了できる。
- **選択モードで短縮できなかったときは、1本ごとの理由を表示する**
  （すでに最短＝迂回率1.0 / 幅混在 / ロック / ズレた同ネット接触の相手と座標 /
  障害物で塞がれている、など）。
- 触らないもの: 円弧を含む連鎖、途中で幅が変わる連鎖、ロックされた配線、
  端子の無い閉ループ、**センターラインから外れた位置で同ネットの銅が接触して
  いる連鎖**（グラフで分割できない接触は、引き直すと切れるため）。
  同ネット同士は障害物とみなさない（接触しても短絡しない）。
- 銅ベタ（ゾーン）は障害物として見ない（塗り直し時にベタ側が配線を避けて
  充填されるので、横切ってもDRC違反にならない）。実行後に B キーで塗り直すこと。

### [pad_zone_wrap.py](pad_zone_wrap.py) — Wrap Pads with Zone (rectangle)

**選択したパッドを長方形のベタ（銅箔ゾーン）で囲む。**
パッド（またはフットプリント）を選択して実行すると設定ダイアログが開き、
「作成」で選択パッド全体のBBox+余白の長方形ゾーンが1つ作られる。

- **層**: 有効な銅箔層のチェックボックスから複数選択できる（1ゾーンが複数層をまたぐ）。
  初期値は選択パッドが載っている層。
- **ネット**: 候補は選択パッドに含まれるネットのみ。**1種類しか無ければ自動で選択済み**。
- **余白・クリアランス・最小幅**をmm単位で指定。余白の初期値は1.0mm
  （サーマルギャップより狭いと、パッド外周のベタがギャップに食われてほぼ見えなくなるため）。
- **パッド接続**はサーマルリリーフ／ベタ直結を選択。
- 「作成後に塗りつぶす」を外した場合は、KiCad上で B キーで塗れる。
- 選んだネットのパッドが範囲内に無い層は、塗りつぶすと孤立扱いで銅が消えるため、
  作成後に警告を出す（ゾーン自体は作られる）。

## 主なパラメータ（各ファイル先頭）

| 変数 | 意味 |
|---|---|
| `GAP_NM` | 部品/ブロック間ギャップ [nm]。異ネットが隣接する場合は0.1mm程度を推奨 |
| `TIME_BUDGET_S` | 並び順最適化（焼きなまし法）に使う時間 [秒] |
| `MAX_ROW_WIDTH_MM` | 配置ブロックの最大幅 [mm]。0なら全体が正方形に近づくよう自動設定 |
| `DENSITY_WEIGHT` | 高さ増加1nmを配線長何nm相当として罰するかの重み |
| `LIVE_UPDATE_S` | （rot のみ）暫定ベスト配置を画面に反映する最短間隔 [秒]。0なら最後だけ描画 |
| `STUB_MAX_MM` | （track_shorten）吸収削除する行き止まりヒゲの最大長 [mm]。これより長い宙ぶらりんは残す |
| `MAX_NODES` | （track_shorten）1本あたりの探索ノード数上限。密集地帯で「見落としの可能性」が出たら増やす（遅くなる） |
| `SEARCH_TIME_S` | （track_shorten）1本あたりの探索時間上限 [秒]。切れた時点でゴール到達済みなら暫定解を使う |

## 既知の制約 / 今後の改善候補

### 配置ツール（dense_pack / min_wire_pack_rot）

- 評価関数はネット等重みのHPWLベースで、GND/電源ベタなど本来配線長を気にしなくて
  よいネットも同列に評価される（ゾーン検出・ネットクラス重み付けが未実装）。
- 多ピン（3ピン以上）ネットはHPWLが実配線長を過小評価する（MST長への置き換えが候補）。
- コートヤードは矩形近似のため、非矩形部品では空間を無駄にすることがある。
- 配置座標は任意のnm値になり、グリッドに乗らない。
- 基板外形・キープアウト・既存トラックは考慮しない。
- 部品数が多いと `min_wire_pack_rot` は評価コストが増え、最適化中はUIが固まる
  （進捗ダイアログと暫定ベスト描画で状況は見える）。

### track_shorten

改善候補（優先度順の目安）:

- **ラバーバンド（pull-tight）フォールバック**: A\*が経路を見つけられない
  密集地帯で、今の経路のトポロジー（障害物のどちら側を通るか）を保ったまま
  45度でピンと張る。探索が要らないので絶対に失敗せず、「複雑な場所では
  何も起きない」を「最低でも弛み取りはされる」に変えられる。
  `seg_ok`/`reduce_bends` がそのまま道具になる。
- **曲げ最小化モード**: 現状は「長さ優先、同長の中で曲げ最少」。長さを少し
  犠牲にしてでも曲げを減らすオプション（曲げ1回あたりの長さペナルティを
  ダイアログで指定）。
- **T字分岐点（シュタイナー点）の移動**: 分岐点は現在固定端子。分岐点の位置
  自体を最適化すれば多ピンネットの総延長をさらに縮められる。
- **ビアの追加・削除（層乗せ替え）**: 現在ビアは固定点。層をまたぐ最短化は
  実質リルーターで、探索・検証とも大幅に重くなるため別ツール級の拡張。
- ~~**斜め障害物の実形状ノード**~~ → 実装済み: 線分障害物には膨張BBoxの角に
  加えて、**端点まわりの8方向リング**と**端子・他障害物の端点から線分への
  垂線の足±法線**のノードを生成する（`corner_candidates`）。長い配線・45度
  配線の「際」や、2本の長い配線に挟まれたチャネルの通過点が拾えるようになった。
  dense_pack のA*も同じノード生成を使う。

既知の制約:

- 円弧を含む連鎖・幅が途中で変わる連鎖は対象外（触らない）。
- カスタムDRCルール（.kicad_dru）はGUI実行時の `GetOwnClearance` 経由でしか
  反映されない（ネットクラス・ローカル上書き・穴/エッジ設定は常に反映）。
- パッド内で完結する旧配線の微小片は削除されず残ることがある
  （パッドの銅に覆われるため実害はない。「基板のクリーンアップ」で除去可）。
- 差動ペア・長さ調整（ミアンダ）は認識しない。等長配線には使わないこと。
